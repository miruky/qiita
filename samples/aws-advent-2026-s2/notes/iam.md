# AWS IAM の学習ノート

IAM は「誰が」「何を」「どのリソースに対して」できるかを決めるサービスです。

## 覚えたこと
- 日々の作業にルートユーザーは使わず、IAM ユーザーや IAM Identity Center のユーザーで作業します。
- ポリシーは JSON で書き、Effect（Allow か Deny）、Action、Resource を組み合わせます。明示的な Deny は Allow より優先されます。
- サービスに権限を渡すときは IAM ロールを使います。Lambda の実行ロールがその例です。
- 必要な権限だけを付ける「最小権限」を心がけます。

## 自分がつまずいた点
ロールの信頼ポリシー（誰がロールを引き受けられるか）と、権限ポリシー（ロールで何ができるか）を混同していました。
